# Запас до старту AI-плану — ручне приймання 2026-11-14

## Реалізація

`StudyPlanPersistenceService::previewNotBeforeUtc()` містить перенесений без
зміни вираз ручного Controller: `CarbonImmutable::now('UTC')->addMinutes(5)->ceilSecond()->getTimestamp()`.
Ручний Controller і лише гілка `propose_study_plan_create` викликають його один
раз перед формуванням огляду та передають результат через чинний `notBeforeUtc`.
Default `preview()` не змінений, тому інші його споживачі не отримують нового запасу.

Чинний `preview()` зберігає `not_before_utc` у захищеному доменному токені.
AI-перевірка expiration вилучає тільки цей серверний параметр із копії параметрів
перед порівнянням з аргументами інструмента. Перед цим токен проходить чинну
валідацію власника, призначення, версії, часу та типу/діапазону межі. Сам токен
і його cutoff не змінюються. Збережена межа використовується під час підтвердження.
Старі токени без цього поля також зберігають чинну поведінку.

Нових «тепер + 5 хвилин» на підтвердженні немає. Незмінний
`confirmWithinTransaction()` регенерує результат із параметрами токена, порівнює
весь склад огляду, перевіряє явну згоду на частковий результат і строго майбутні
старти перед вставкою та перед комітом. Неактуальний огляд відхиляється; новими
сесіями його не підмінюють.

Схема інструмента, чатове підтвердження/receipts, міграції, ручне й автоматичне
відновлення, adaptive replanning, перенесення однієї сесії та нагадування не змінені.

## Фактично виконано

Початковий `git status --short` порожній, гілка `main`. Прочитано AGENTS.md,
зазначені Controller/Services, суміжні planner/confirmation/resource/request,
маршрути, релевантні наявні тести, архітектурну/доменну/бізнес-документацію,
контракти планування та ADR-004.

Для ручного приймання створено окремі MySQL datadir/socket і БД
`planner_plan_cutoff`, без мережевого доступу до цієї MySQL. `SELECT @@datadir`
підтвердив ізоляцію до міграцій. Застосовано чинні міграції; нових немає.
Використано окремі процесні DB env, APP_KEY та APP_CONFIG_CACHE, без змін `.env`.
Тимчасову MySQL після перевірки зупинено.

Ручний PHP CLI-сценарій поза репозиторієм завантажував звичайний Laravel kernel.
Для граничних моментів установлено контрольований Carbon/CarbonImmutable clock.
AI-пропозиції створювалися справжнім `PlanningActionService::prepare()`, включно
з його перевіркою expiration. Токен вручну декодувався чинним
`StudyPlanConfirmationService`. Збереження виконувалося справжнім
`StudyPlanPersistenceService::confirm()` із MySQL-транзакцією. Ручний огляд
викликав справжній `StudyPlanController::preview()` із валідованим FormRequest.
Це перевірка Controller/Services/БД у процесі PHP, без HTTP-сервера чи тестового
framework. Модель/LLM не викликалися.

Для кожного сценарію — окремий власник UTC, вікно суботи 10:00–12:00,
мінімальна сесія 10 хвилин, оцінка завдання 30 хвилин. Початковий clock:
`2026-11-14T10:00:00.250000Z`.

| Сценарій | Фактичний результат |
| --- | --- |
| Доступність починається зараз, deadline 12:00 | AI: confirmation_required, 10:05:01–10:35:01 UTC, 1800 с. У токені cutoff=10:05:01; аргументи інструмента не містять часу/межі |
| Підтвердження до старту | О 10:04:30 збережено рівно одну сесію 10:05:01–10:35:01. Це також перевіряє відсутність нового запасу на підтвердженні: новий now+5m пересунув би початок |
| Підтвердження після старту | О 10:05:02, до expiry 10:15:00: StudyPlanConflictException, у власника 0 сесій. Жодної підміни новим стартом |
| Після зрізу до deadline 10:12 замало часу | Менше мінімальних 10 хв: no_actionable_plan, sessions=[], proposal=null, 0 сесій у БД |
| Частковий план до deadline 10:20 | Огляд 10:05:01–10:20:00, 899 с; required_consent=[accept_partial]. О 10:01 без згоди ValidationException по accept_partial, 0 записів. З true — рівно переглянута сесія |
| Склад огляду змінився | Після огляду доступність змінена на початок 10:15. Підтвердження о 10:01: StudyPlanConflictException, 0 сесій; альтернативний план не збережено |
| Ручний огляд | Для повного, порожнього та часткового випадків реальний Controller повернув той самий plan, що й попередній вираз обчислення межі, явно переданий у preview(); точне порівняння всього plan=true |
| Ціла секунда | При now=10:00:00.000000 helper повернув 10:05:00; при .250000 — 10:05:01 |

Перша спроба підготовки ручних даних зупинилась через рядок priority замість
чинного int-backed enum. Виправлено лише тимчасовий сценарій, повтор виконано
з окремими власниками; application code через це не змінювався.

## Перевірено лише за кодом

- Повний чат: фіналізація пропозиції, AiPendingAction, authenticated confirm,
  savepoint, receipt/replay, відображення помилок у чаті — не запускалися наскрізно.
  Вони делегують чинному confirmWithinTransaction; цей writer перевірено через
  публічний confirm, який викликає його в транзакції.
- Сумісність старих AI-токенів без cutoff, незмінність решти tool arguments binding,
  підписи/expiry, ownership і перевірка після очікування owner lock.
- Поведінка recovery, adaptive replanning, перенесення сесії та нагадувань;
  їхні реалізації, default preview і відповідні гілки виконання не змінені.
- Протермінування токена та просування clock під час великої вставки; відповідні
  чинні перевірки перед комітом залишилися без змін.

Автоматизованих тестів не додавали, не редагували й не запускали.
