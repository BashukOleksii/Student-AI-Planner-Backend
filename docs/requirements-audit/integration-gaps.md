# Integration gaps and readiness

> Current implementation supersession: Historical calendar presentation, semester AI editing and absent-trigger findings below are superseded by the current source and [implementation review](../learning-recovery-implementation.md). Automatic recovery now proposes through an authenticated review feed and never applies unattended. Remaining gaps are verification, bounded account/horizon coverage, original-source fidelity, frontend integration and operational scheduler/delivery/LLM readiness; see [contract](../automatic-learning-recovery.md).

Applies to the checkout and requirement IDs in [functional coverage](functional-coverage.md). Findings below are source inspection results, not deployed-system observations. Test references identify coverage to execute; only [verification evidence](verification-evidence.md) records executions.

## I1 — Calendar source integration exists; REST presentation is split

`FreeTimeService::calendarSources` calls `CalendarBusyIntervalService::between`. That service loads owned semester schedules via `EffectiveScheduleService::schedulesInRange/forRange`, expands effective occurrences, includes independent active legacy Lessons and suppresses imported legacy history inside its own authoritative semester period. Replacement provenance follows owned originals, including soft-deleted history, and rejects invalid references. Namespaced class identities cannot be confused with numeric session exclusions. See [FreeTimeService](../../app/Services/Planning/FreeTimeService.php), [CalendarBusyIntervalService](../../app/Services/Planning/CalendarBusyIntervalService.php), [EffectiveScheduleService](../../app/Services/Schedule/EffectiveScheduleService.php).

`PlanningContextService::load` uses those sources for free intervals and buffered break anchors. [StudyPlanningService](../../app/Services/Planning/StudyPlanningService.php), [StudyReplanningPreviewService](../../app/Services/Planning/StudyReplanningPreviewService.php) and [StudySessionReschedulingService](../../app/Services/Planning/StudySessionReschedulingService.php) reuse deterministic context/candidate validation. [StudyRecoveryPreviewService](../../app/Services/Planning/StudyRecoveryPreviewService.php) delegates to the plan preview rather than implementing another calendar. Confirmations reload current sources under transactions: [StudyPlanPersistenceService](../../app/Services/Planning/StudyPlanPersistenceService.php), [StudyReplanningPersistenceService](../../app/Services/Planning/StudyReplanningPersistenceService.php).

[EffectiveScheduleReadService](../../app/Services/AI/Tools/EffectiveScheduleReadService.php) uses the same occupancy for AI date reads, returns virtual semester identities, local offsets, source types and truncation metadata (100 lessons). Legacy IDs stay numeric. Semester `lesson_type` belongs to the occurrence and may be null; all types block study time.

However [ScheduleController](../../app/Http/Controllers/Api/ScheduleController.php) uses [ScheduleService](../../app/Services/Schedule/ScheduleService.php), which reads concrete active Lessons only. Semester REST date/week reads are separate in [SemesterScheduleController](../../app/Http/Controllers/Api/SemesterScheduleController.php). A frontend that only calls `/schedule/today` may show fewer classes than the planner/AI blocks. This is an integration contract boundary, not evidence that the shared planner calendar is absent. Decide whether separate views satisfy S1 before changing contracts. Combined day/week endpoint semantics, pagination, ordering and cross-period legacy suppression must be specified if a unified API is adopted.

Existing coverage: [SemesterPlanningCalendarTest](../../tests/Feature/SemesterPlanningCalendarTest.php), especially `test_legacy_imports_and_their_replacements_are_suppressed_only_in_their_own_authoritative_period`, `test_preview_avoids_semester_and_confirmation_rejects_changed_calendar_atomically`, `test_replanning_and_manual_rescheduling_share_occupancy_and_preserve_sessions_on_conflict`; [AiToolsIntegrationTest](../../tests/Feature/AiToolsIntegrationTest.php) mixed-source, replacement, corruption and read-only tests. [BackendIntegrationSmokeTest](../../tests/Feature/BackendIntegrationSmokeTest.php) compares equivalent legacy fields rather than asserting identical REST/AI schemas. Database integration was not rerun in this audit.

## I2 — Recovery is calculated automatically when requested, not triggered autonomously

[TaskService::miss](../../app/Services/Tasks/TaskService.php) changes the Task status only. [StudyRecoveryPreviewService](../../app/Services/Planning/StudyRecoveryPreviewService.php) reports missed and past-planned sessions; it does not infer missed/completed status from time. [PlanningActionRegistry](../../app/Services/AI/Actions/PlanningActionRegistry.php) now includes session complete and mark-missed proposals, in addition to plan/replanning/rescheduling proposals. This resolves the earlier absence of an AI session lifecycle bridge. The [AgentOrchestrator](../../app/Services/AI/AgentOrchestrator.php) requires fresh recovery diagnostics after confirmation. [TaskActionConfirmationService](../../app/Services/AI/Actions/TaskActionConfirmationService.php) owns authenticated execution/receipts, rather than conversational consent.

There is no unattended task relocation trigger in [routes/console.php](../../routes/console.php), and no replanning Job under `app/Jobs/`. A deadline or schedule edit does not silently rebuild sessions. T4/X2 wording must be resolved before adding a background writer: opt-in, trigger frequency, horizon, consent, duplicate prevention, failure reporting and missed-state authority are all unresolved. Existing coverage: [TaskMissedStatusTest](../../tests/Feature/TaskMissedStatusTest.php), [StudyRecoveryApiTest](../../tests/Feature/StudyRecoveryApiTest.php), [AiSessionLifecycleActionsTest](../../tests/Feature/AiSessionLifecycleActionsTest.php), [StudyReplanningConfirmationTest](../../tests/Feature/StudyReplanningConfirmationTest.php).

## I3 — AI action surface is useful but not complete semester management

[LessonActionRegistry](../../app/Services/AI/Actions/LessonActionRegistry.php) exposes create/update/cancel/replacement for concrete Lessons. [AgentOrchestrator](../../app/Services/AI/AgentOrchestrator.php) explicitly prohibits using a legacy Lesson as a workaround for a semester edit. No semester-management/import, catalog lookup or Task delete/miss proposal was found in the registries. Discovery of subject/teacher names is therefore not equivalent to owning a catalog ID. [TaskActionRegistry](../../app/Services/AI/Actions/TaskActionRegistry.php), [SubtaskReminderActionRegistry](../../app/Services/AI/Actions/SubtaskReminderActionRegistry.php), [AvailabilityActionRegistry](../../app/Services/AI/Actions/AvailabilityActionRegistry.php) and [PlanningActionRegistry](../../app/Services/AI/Actions/PlanningActionRegistry.php) are the actual action contract, not the example tool names from section 3 of the source.

Tests: [AiLessonActionsTest](../../tests/Feature/AiLessonActionsTest.php), [AiAvailabilityActionsTest](../../tests/Feature/AiAvailabilityActionsTest.php), [AiSessionLifecycleActionsTest](../../tests/Feature/AiSessionLifecycleActionsTest.php), [AgentOrchestratorTest](../../tests/Unit/AgentOrchestratorTest.php). Provider HTTP fakes cannot establish that a real model selects correct tools, resolves ambiguity or produces accurate Ukrainian narratives. A1/A2 remain unverified even with deterministic adapter tests.

## I4 — Reminder code is present; operational delivery is not proven

[ReminderDeliveryService::dispatchDue/process](../../app/Services/Reminders/ReminderDeliveryService.php) selects bounded due records, serializes by owner, revalidates target eligibility and atomically writes an owned database notification and sent status. Corrupt candidates roll back and count as failures; retries must not create duplicate receipts. [NotificationInboxService](../../app/Services/Notifications/NotificationInboxService.php) exposes owned inbox/read state. [routes/console.php](../../routes/console.php) schedules `reminders:dispatch-due --limit=100` every minute. This database-inbox path is synchronous; it is not evidence of email/push transport and does not require a notification queue worker.

Tests: [ReminderDeliveryTest](../../tests/Feature/ReminderDeliveryTest.php), [ReminderDeliveryConcurrencyTest](../../tests/Feature/ReminderDeliveryConcurrencyTest.php), [NotificationInboxApiTest](../../tests/Feature/NotificationInboxApiTest.php). No scheduler process, delivery latency/backlog, monitoring, or actual frontend inbox rendering was observed here. Decide accepted latency/backlog and alerting thresholds. Cancellation is supported, physical reminder deletion is not exposed by [routes/api.php](../../routes/api.php); confirm N3 semantics.

Password recovery is a separate operational path: [PasswordManagementService](../../app/Services/Auth/PasswordManagementService.php) dispatches [SendPasswordResetLink](../../app/Jobs/SendPasswordResetLink.php). Queue worker, trusted frontend reset origin, session configuration and real mailbox receipt need verification. [PasswordManagementTest](../../tests/Feature/PasswordManagementTest.php) supplies deterministic coverage, not a delivered-email receipt.

## I5 — Progress reports have defined, limited semantics

[ProgressStatisticsService](../../app/Services/Progress/ProgressStatisticsService.php) supplies completion percentage, current pending/missed/completed/overdue counts and period/subject activity. [ProgressTrendsService](../../app/Services/Progress/ProgressTrendsService.php) fills local dates; [ProgressComparisonService](../../app/Services/Progress/ProgressComparisonService.php) explicitly returns `historical_snapshot: false`. Periods are bounded to 31 dates; comparisons use equal nonoverlapping periods. Sessions are attributed by start with full scheduled duration; constraint workload instead accounts for actual local-day/week overlap. Unknown actual minutes are not zero. Reopening work or editing deadlines changes current persisted facts, not an immutable historical report.

[WorkloadAdviceService](../../app/Services/Planning/WorkloadAdviceService.php) provides on-demand deterministic constraints and measured persisted overload. No dedicated workload-advice AI tool is present in [ToolRegistry](../../app/Services/AI/Tools/ToolRegistry.php); statistics reads and planning diagnostics remain available. Tests: [ProgressStatisticsApiTest](../../tests/Feature/ProgressStatisticsApiTest.php), [ProgressTrendsIntegrationTest](../../tests/Feature/ProgressTrendsIntegrationTest.php), [ProgressComparisonIntegrationTest](../../tests/Feature/ProgressComparisonIntegrationTest.php), [WorkloadAdviceApiTest](../../tests/Feature/WorkloadAdviceApiTest.php). Downloadable reports and immutable history are not requirements established by the source. Decide wording/cohort semantics before expanding analytics.

## I6 — Security and persistence exist; current runtime assurance remains bounded

[API routes](../../routes/api.php) enforce authentication and now throttle login/registration. [TaskPolicy](../../app/Policies/TaskPolicy.php) and [SemesterSchedulePolicy](../../app/Policies/SemesterSchedulePolicy.php) hide foreign resources; services repeat owner-scoped reads. [SaveWeeklyLessonRuleRequest](../../app/Http/Requests/SaveWeeklyLessonRuleRequest.php) validates scalar types and lesson fields, with ownership enforced by the management service. [TaskResource](../../app/Http/Resources/TaskResource.php) and [ScheduleLessonResource](../../app/Http/Resources/ScheduleLessonResource.php) bound presentation; [ToolExecutor](../../app/Services/AI/Tools/ToolExecutor.php) hides unexpected SQL details.

The [semester foundation migration](../../database/migrations/2026_11_10_000001_create_semester_schedule_foundation.php) adds composite ownership/provenance FKs and uniqueness; the [reminder migration](../../database/migrations/2026_10_05_000011_create_reminders_table.php) has nullable target FKs and due/owner indexes. Legacy FK existence alone is not an ownership guarantee. Source validation remains necessary. No deployed schema, isolation level, lock behavior, restore procedure or network boundary was verified. Tests: [AcademicContextSecurityTest](../../tests/Feature/AcademicContextSecurityTest.php), [AiReadinessHardeningTest](../../tests/Feature/AiReadinessHardeningTest.php), [AuthRateLimitTest](../../tests/Feature/AuthRateLimitTest.php), [SemesterScheduleMigrationTest](../../tests/Feature/SemesterScheduleMigrationTest.php).

## I7 — Historical conclusions conflict with current implementation

The introductory paragraphs of [architecture.md](../architecture.md), [domain-model.md](../domain-model.md) and foundation-only [ADR-006](../decisions/ADR-006-semester-schedule-foundation.md) describe a stage where planning/AI remained on concrete Lessons. I1 establishes that this is no longer the complete current behavior. [ADR-010](../decisions/ADR-010-single-teacher-and-custom-saturdays.md) supersedes earlier multi-teacher assumptions. The current [SaveWeeklyLessonRuleRequest](../../app/Http/Requests/SaveWeeklyLessonRuleRequest.php) requires one scalar teacher for writes. Existing teacherless historical reads are not proof that new writes permit missing teachers.

The older [Stage 19 assessment](../stage19/backend-requirements-audit.md) says login/register throttling is absent and quotes older tool counts; current [routes/api.php](../../routes/api.php), [AuthRateLimitTest](../../tests/Feature/AuthRateLimitTest.php) and [PlanningActionRegistry](../../app/Services/AI/Actions/PlanningActionRegistry.php) contradict those assertions. Historical reports and prior-turn test counts must not be used as current-head execution evidence. Reconcile prose with current code through a small documentation task; do not silently reverse the implemented calendar/confirmation architecture.
