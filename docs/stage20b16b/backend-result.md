## Review and enablement limits

Deployment requires the repository variable
`LIGHTSAIL_BACKEND_DEPLOY_ENABLED=true`, production Environment secrets and the
manual server setup in [the runbook](../lightsail-backend-deployment.md). No flag
was enabled and no external GitHub configuration was modified or asserted verified.
The server's actual checkout, host fingerprint, sudo grants, units, permissions
and applied schema were deliberately not inspected over SSH during implementation.

The current in-place layout entails a brief Backend outage. After code/dependency
mutation, failure retains maintenance and attempts service shutdown; a persistent
marker blocks blind retries. Recovery favors completion of the tested SHA or a
reviewed forward revert/fix. It never reports an old version as active after a
partial update. Power failure and failed containment require operator inspection.

Production MySQL 8.0 compatibility of future schema changes requires separate
review/testing on a matching disposable 8.0 instance; the preserved CI database
remains 8.4. This stage introduces no migration and does not automatically apply
one. Hosted GitHub Actions and real production smoke tests are not claimed run.
