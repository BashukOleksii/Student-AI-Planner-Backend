# Простий огляд планування та сторінка сесії

## Що змінено

1. **Форма.** Прибрано підпис про 31 день у формі огляду; чинна валідація
   періоду залишилася. Завдання й кроки вибираються пошуковими полями з підтримкою
   клавіатури. Пошук на сервері, затримка 250 мс, до 20 варіантів на сторінку.
   Відбір використовує чинний PlanningWorkSelectionService: виконана, прострочена
   або повністю зарезервована робота не пропонується для нового планування.
   Для перенесення допускається перегляд уже зарезервованої роботи, як і раніше.
   Підзавдання належать лише обраному власному завданню; виконані не пропонуються.
   Порожні списки та завершені кроки мають короткі повідомлення. Перед запитом
   огляду вибір перевіряється повторно: завершений тим часом крок не підміняється
   плануванням батьківського запису чи всієї роботи.
2. **Огляд.** Прибрано довільне виведення об’єкта відповіді та технічний повний
   розрахунок. Залишено підсумок часу, запропоновані сесії, нерозміщений залишок,
   українські причини й наступний крок. Непридатна робота показується стисло,
   довгі списки згортаються після п’яти рядків. Підтвердження часткового плану,
   поділу й скасування без заміни збережено. Коли змін немає, підтвердження відсутнє.
   Нижні посилання на доступність і завдання прибрано; після збереження залишається
   повернення до сесій. Чинне перечитування після невідомого результату не змінено.
3. **Окрема сесія.** Назва в картці стала звичайним текстом. Прибрано додаткову
   навігацію, посилання на історію та розкривний час завершення на сторінці деталей.
   Після завершення студент залишається на сторінці: короткий стан, фактичні хвилини
   й одна кнопка «Повернутися до сесій». Прапорець завершення роботи лишається
   необов’язковим і вимкненим; фактичні хвилини обов’язкові. Переходи та атомарне
   завершення роботи не змінювалися. Історія у загальному списку залишається.
4. **Backend.** Presenter перекладає результати, не перераховує правила й не
   змінює алгоритм. Технічні коди збережено для сумісності окремо від пояснень;
   огляд у Vue використовує готові тексти. Невідомий код отримує нейтральне
   українське пояснення, його назва не відображається.

## Додатковий контракт API

- `GET /api/planning/work-options?search=…&page=1&mode=planning`:
  `data: [{id, title}]`, `meta.current_page`, `last_page`, `total`.
- Параметр `task_id` повертає доступні підзавдання цього власного завдання та
  `meta.has_subtasks`, `all_subtasks_completed`, `task_available`.
  Необов’язковий `subtask_id` дозволяє повторно перевірити саме вибраний крок,
  зокрема вибраний на наступній сторінці пошуку. Чужі/невідповідні зв’язки — 404.
- `mode=replanning` зберігає можливість перегляду вже зарезервованої роботи.
  Перелік варіантів не обіцяє наявності вільного календарного часу: це визначає
  незмінений огляд планування. Усі GET залишаються без запису.
- План: `user_summary.title`, `user_summary.next_step`,
  `work_results[].explanations`, `excluded_items[].explanations`,
  `warnings[].explanations`.
- Перепланування: ті самі поля й `session_results[].explanations`.
- Результат перепланування/перенесення: `user_summary.title` і `next_step`.
- Сесія: `status_label`, наприклад «Сесію завершено». Поля `status`,
  `actual_minutes`, часові поля та попередні контракти не змінено.

## Перевірка

Backend: використано тільки вже наявний `scripts/testing/phpunit-disposable-mysql.sh`.
Не додано постійної тестової БД, міграцій чи демозаписів; робочу БД не очищено.

- Огляд, пояснення й API плану: 114/114 тестів, 1016 assertions.
- Пояснення, огляд/підтвердження перепланування й lifecycle сесій:
  320/320 тестів, 3167 assertions.
- Frontend: 112/112 тестів у 8 файлах; `npm run type-check` і `npm run build` успішні. Додано тести пошукового поля, клавіатури, невідомого пошуку,
  українських пояснень без технічних ключів, завершеного кроку й повторної перевірки.
  Тести завершення сесії перевіряють обидва підписи прапорця, початкове вимкнення,
  фактичні хвилини, відсутність автоматичного повтору POST та повернення до списку.

Це цільова автоматизована перевірка, включно з монтуванням Vue і переходами router.
Окремий ручний прогін у справжньому браузері й навантажувальне тестування не виконувалися.
Пошук має обмежену видачу, але для перевірки доступності роботи використовує чинний
вибір роботи власника, без нового кешу чи індексів. Алгоритм і статуси не змінено.

## Ручні сценарії

1. Відкрити `/planning/preview`, знайти незавершене завдання за частиною назви,
   вибрати крок, дати й «Створити огляд». Перевірити сесії, залишок і українські
   пояснення; за потреби явно погодити частковий результат перед збереженням.
2. Вибрати крок, завершити його в іншій вкладці, повернутися й створити огляд.
   Має з’явитися повідомлення про недоступну роботу без запиту планування для
   батьківського завдання. Завершені кроки не мають з’являтися в новій видачі.
3. Вибрати період без доступного часу. Побачити коротку причину та наступний крок,
   без технічних кодів, повного розрахунку й кнопки підтвердження порожнього плану.
4. Відкрити розпочату сесію, ввести фактичні хвилини, залишити прапорець вимкненим
   і завершити. Робота залишається відкритою; видно стан і фактичний час.
5. В іншій розпочатій сесії ввімкнути прапорець завершення роботи. Для підзавдання
   він стосується лише цього кроку. Якщо є інші майбутні сесії, перевірити серверне
   попередження та явно погодитися. Перевірити чинний атомарний результат.
6. Після успішного завершення натиснути «Повернутися до сесій». Відкривається список;
   на сторінці результату немає розкривного часу завершення чи посилання на історію.
